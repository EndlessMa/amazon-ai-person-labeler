# 架构与安全边界

## 进程边界

Electron 渲染进程只负责界面，启用 `contextIsolation`、sandbox，并关闭
`nodeIntegration`。渲染进程不能直接访问文件系统或启动子进程；预加载层只暴露逐项定义的 IPC
方法。所有文件选择、扫描、解压、XMP 读写与哈希都在主进程完成。

应用不主动访问互联网、第三方 API 或遥测服务。允许访问用户已经通过操作系统挂载的本地盘、NAS
和同步目录。

## 处理流水线

1. 解析输入，并把 canonical path 相同的源文件去重。
2. 对压缩包先读取技术索引并执行路径、加密、分卷、嵌套、SFX 和体积检查。
3. 只在输出父目录下创建临时解压目录；成功、失败或取消后都尝试清理。
4. 检查真实文件签名、扩展名、静态 PNG、文件大小和像素数。
5. 读取所有标准内嵌 XMP 包，精确分析 `dc:subject/rdf:Bag/rdf:li`。
6. 记录源文件大小、mtime 和 SHA-256；处理前再次核对，变化的文件失败。
7. 在新的批次目录处理副本；从不覆盖或原地写入源文件。
8. 用独立解析路径二次校验目标值、图像载荷哈希和非目标元数据语义值。
9. 只有通过二次校验的图片进入批次目录；所有来源都平铺输出，重名图片自动追加
   ` (2)`、` (3)`。批次目录不生成报告、日志或中间子目录。

## 标签语义

- 仅当 `rdf:li` 的完整值区分大小写地等于
  `contains-synthetic-performer` 才算标准值；不做 trim。
- 0 个标准值为未标记；1 个为合规；大于 1 个为“已标记但需规范”。
- 大小写、空白或拼写近似值会保留并提示，不会被当成标准值。
- 添加模式保证输出恰好一个标准值。
- 移除模式删除所有标准值，并保留其他 subject 值。
- 畸形 XMP/EXIF 不尝试修复，文件按失败处理。

## 无损判据

“不改变图片”采用可执行的验收定义：

- JPEG 的压缩扫描数据、PNG 的 IDAT 数据字节一致。
- 像素尺寸和图像格式一致。
- 除目标 `dc:subject` 外，其他元数据字段和值语义一致。
- 允许 XMP 包的序列化顺序、空白和 padding 改变。

整个输出文件的 SHA-256 通常会因 XMP 变化而不同，不作为跨平台一致性的要求。

## 容量与故障

- 最多扫描 20,000 个条目、接受 10,000 张支持图片。
- 解压后总量最多 50 GB；单图最多 500 MB、100,000,000 像素。
- 写入前要求可用空间不小于估算峰值加 `max(10%, 2 GB)`。
- 单文件失败不终止其他文件；磁盘耗尽或用户取消会停止启动新任务，已经通过验证的输出保留。
- 批次期间在本地 app-data 写恢复记录；正常完成后删除。异常退出后下次启动可导出或删除记录，不提供断点续传。
